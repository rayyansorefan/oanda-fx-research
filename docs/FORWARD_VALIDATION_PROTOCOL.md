# Forward FX validation milestone

No further live admission or risk restrictions are relaxed. The existing champion and already-paper-only challenger retain their rules. Data coverage is widened for preliminary paper candidates so missing H4/D history cannot quietly bias the comparison.

## What counts

The locked holdout starts **29 October 2026 at 07:00 Europe/London**. Earlier replay and counterfactual results remain development evidence. Both arms use common completed M15/H1/H4/D history. Missing common history is excluded and reported, not called a losing strategy or a conflicting trend.

The protocol pins the rule-code digest and its own initial digest. Changing code, thresholds, holdout start or acceptance rules invalidates this study. There is no automatic promotion or change to `signals.json` from this validator.

The initial eligibility floors are 20 scored London days and 100 independent scored pair/day outcomes per arm. Only the earliest scored fill for a pair on a London day enters the statistical sample. Return differences are clustered by day, with zero for an arm's abstention, and a pre-registered fixed-seed 10,000-resample bootstrap. These floors are conservative review criteria, not a power calculation or evidence that an edge exists.

## Timing evidence

The audit records separately:

1. Source collection and immutable plan creation.
2. Completed trigger candle and actual detection time.
3. Successful repository readback.
4. First observed public serving of the matching plan/trigger and source snapshot.
5. Actual provider delivery receipt or user acknowledgement, with a source reference.

Items 3 and 4 do not establish item 5. A source timestamp, GitHub run, prepared message, public feed, or passing test is never substituted for a ChatGPT push delivery receipt. The currently available automation tools do not expose a device delivery receipt. Until actual evidence is present, timely user delivery remains unverified and cannot validate a simulated entry. Any verified receipt must precede the scored entry by at least the fixed one-minute manual response allowance.

No new messages or scheduled tasks are created by the validator. Existing monitoring, assessments and quiet hours remain intact.

## Costs and outcomes

OANDA ask buys / bid sells and opposite-side exits already include spread. The validator does not subtract spread a second time. It separately reports 0, 0.25 and 0.5 pip per-side slippage scenarios and adverse stop gaps using the exit bar's opening quote. These are stress assumptions, not observed broker fills.

Positions crossing New York 17:00 are flagged when financing is unverified. Additional broker costs must have documented provenance and a finite non-negative `additional_broker_cost_r`; zero is not inferred. OANDA paper outcomes never establish Pepperstone orders or fills.

## Deployment versus evidence

`data/forward_validation.json` reports the study's actual state, coverage exclusions, independent sample counts, cost scenarios and missing evidence. `data/signal_delivery_audit.json` preserves event clocks and public serving observations. No user receipt is generated by this code.

A deployment may pass while this report says HOLDOUT_NOT_STARTED, PROTOCOL_CHANGED or INSUFFICIENT_VALIDATION_EVIDENCE. That is expected. A measured improvement still requires sufficient untouched holdout results, timely delivery evidence, realistic costs and independent review. No promotion follows merely from signal frequency, sample counts or a positive point estimate.

At the 23:39 source used to design this instrumentation, 16/65 pairs had full deep history, and **all four strict preliminarily eligible candidates were among those 16**. This snapshot therefore does not demonstrate a strict qualifying pair was excluded by the chart cap. The broader paper prequalification is now measured separately and receives its own deep collection.

The 130 route evaluations represent 65 distinct pairs. Rejection reasons overlap. Neither route rejection totals nor sums of per-reason pair counts are an independent trade count.
